## 1. ภาพรวมระบบ (System Overview)

โปรแกรมออกใบรับซ่อมสินค้า (Repair Ticket System) เป็นโปรแกรมประเภท Windows Desktop Application พัฒนาด้วย **C# Windows Forms (.NET 8.0)** เพื่อใช้สำหรับร้านรับซ่อมอุปกรณ์/เครื่องใช้ไฟฟ้า/คอมพิวเตอร์และมือถือ โดยมีจุดประสงค์หลักเพื่อ:
1. บันทึกข้อมูลการรับซ่อมสินค้าของลูกค้าได้อย่างรวดเร็วและถูกต้อง
2. พิมพ์ใบรับซ่อมสินค้าขนาด A4 ที่ตัดแบ่ง 2 ส่วน (ส่วนของร้านค้า และส่วนของลูกค้า) ในแผ่นเดียวกัน
3. ค้นหาประวัติใบงานย้อนหลังเพื่อเรียกดู แก้ไขข้อมูล หรือสั่งพิมพ์ซ้ำได้ทันที
4. จัดการข้อมูลชื่อร้าน ที่อยู่ และเบอร์โทรศัพท์ผ่านหน้าจอโปรแกรมโดยตรง และบันทึกเข้าสู่ฐานข้อมูล SQLite อัตโนมัติ

## 3. ข้อกำหนดฐานข้อมูล (Database Specification)

- **เครื่องยนต์ฐานข้อมูล:** SQLite ผ่าน NuGet Package `Microsoft.Data.Sqlite` (เวอร์ชัน 8.x)
- **ตำแหน่งไฟล์:** `repair_shop.db` อยู่ในโฟลเดอร์รันโปรแกรม (Application Base Directory)
- **การสร้างตารางอัตโนมัติ (Auto-Bootstrap):** เมื่อเปิดโปรแกรม ระบบจะตรวจสอบและรันคำสั่ง `CREATE TABLE IF NOT EXISTS` อัตโนมัติ

### 3.1 ตาราง `RepairJobs` (ข้อมูลงานซ่อม)
| ฟิลด์ (Column) | ชนิดข้อมูล (Data Type) | ข้อกำหนด (Constraints) | คำอธิบาย (Description) |
| :--- | :--- | :--- | :--- |
| `Id` | `INTEGER` | `PRIMARY KEY AUTOINCREMENT` | ลำดับอ้างอิงภายใน |
| `JobNo` | `TEXT` | `NOT NULL UNIQUE` | เลขที่ใบงาน รูปแบบ `YYMMDD-hhmmss` (เช่น `261119-100524`) |
| `JobDate` | `TEXT` | `NOT NULL` | วันที่รับซ่อม รูปแบบ `yyyy-MM-dd HH:mm` |
| `CustomerName` | `TEXT` | `NOT NULL` | ชื่อ-นามสกุล หรือชื่อลูกค้า |
| `CustomerPhone` | `TEXT` | `NOT NULL DEFAULT ''` | เบอร์โทรศัพท์ลูกค้า (เน้นความชัดเจนทั้งในฟอร์มและใบพิมพ์) |
| `DeviceSymptom` | `TEXT` | `NOT NULL` | อุปกรณ์และรายละเอียดอาการเสีย |

**ดัชนี (Index):**
- `idx_repairjobs_search`: สร้างบนคอลัมน์ `(JobNo, CustomerName, CustomerPhone)` เพื่อรองรับการค้นหาความเร็วสูง

### 3.2 ตาราง `ShopSettings` (ข้อมูลร้านค้าและการจำค่าเครื่องพิมพ์)
| ฟิลด์ (Column) | ชนิดข้อมูล (Data Type) | ข้อกำหนด (Constraints) | คำอธิบาย (Description) |
| :--- | :--- | :--- | :--- |
| `Id` | `INTEGER` | `PRIMARY KEY CHECK (Id = 1)` | ลำดับข้อมูล (บังคับแถวเดียว Id=1) |
| `ShopName` | `TEXT` | `NOT NULL` | ชื่อร้านค้า |
| `ShopAddress` | `TEXT` | `NOT NULL` | ที่อยู่และเบอร์โทรศัพท์ติดต่อของร้าน |
| `DefaultA4Printer` | `TEXT` | `NOT NULL DEFAULT ''` | ชื่อเครื่องพิมพ์ A4 ที่เลือกไว้ล่าสุด (Persistent Memory) |
| `DefaultPosPrinter` | `TEXT` | `NOT NULL DEFAULT ''` | ชื่อเครื่องพิมพ์ POS 58mm ที่เลือกไว้ล่าสุด (Persistent Memory) |
| `LastPrintFormat` | `INTEGER` | `NOT NULL DEFAULT 0` | รูปแบบการพิมพ์ที่เลือกไว้ล่าสุด (0=A4, 1=POS 58mm) |

**การใส่ข้อมูลเริ่มต้น (Seed Data):**
หากตาราง `ShopSettings` ยังไม่มีข้อมูล จะแทรกค่าตั้งต้นอัตโนมัติ:
- `ShopName` = `"ร้านซ่อมอุปกรณ์ด่วน (Smart Repair Shop)"`
- `ShopAddress` = `"123/45 ถ.สุขุมวิท แขวงคลองเตย เขตคลองเตย กรุงเทพฯ 10110 โทร. 081-234-5678"`

### 3.3 ตาราง `WordDictionary` (คลังคำศัพท์ช่างซ่อมสไตล์ Gboard)
| ฟิลด์ (Column) | ชนิดข้อมูล (Data Type) | ข้อกำหนด (Constraints) | คำอธิบาย (Description) |
| :--- | :--- | :--- | :--- |
| `WordId` | `INTEGER` | `PRIMARY KEY AUTOINCREMENT` | รหัสอ้างอิงคำศัพท์ |
| `WordText` | `TEXT` | `NOT NULL UNIQUE` | ข้อความคำศัพท์ช่างซ่อม (Unique ป้องกันคำซ้ำ) |
| `UsageCount` | `INTEGER` | `NOT NULL DEFAULT 1` | ความถี่การใช้งาน (ใช้จัดอันดับคำแนะนำยอดนิยม) |

**ดัชนี (Index):**
- `idx_worddictionary_lookup`: สร้างบนคอลัมน์ `(WordText, UsageCount DESC)` เพื่อรองรับการค้นหาแบบ Contains/LIKE และเรียงลำดับความถี่สูงสุดทันที

**คำศัพท์เริ่มต้นในระบบและการจัดลำดับคำสำคัญ (Seed Words & Top Priority Words):**
ระบบกำหนดคำศัพท์งานซ่อมที่พบบ่อยไว้ล่วงหน้า โดยกำหนดให้ 3 คำสำคัญต่อไปนี้อยู่ **ลำดับหน้าสุด (Top Priority)** เสมอ:
1. `ล้างเครื่อง` (ลำดับที่ 1)
2. `กระดาษติด` (ลำดับที่ 2)
3. `สีไม่ครบ` (ลำดับที่ 3)

ตามด้วยคำศัพท์งานซ่อมอื่นๆ ที่พบบ่อย:
- `จอแตก`, `เปิดไม่ติด`, `ชาร์จไม่เข้า`, `แบตเสื่อม`, `ลงวินโดวส์ใหม่`, `เปลี่ยนอะไหล่`
- `โดนน้ำ`, `จอฟ้า`, `เครื่องร้อน`, `ติดไวรัส`, `เปลี่ยนหน้าจอ`, `เปลี่ยนแบตเตอรี่`, `เพิ่ม RAM`, `อัปเกรด SSD`, `พัดลมไม่หมุน`, `ลำโพงแตก`, `คีย์บอร์ดเสีย`, `ทัชสกรีนไม่ติด`, `สวิตช์เสีย`, `บอร์ดช็อต`, `ไฟไม่เข้า`, `เครื่องค้าง`, `กล้องไม่เปิด`, `ไมค์ไม่ดัง`

ทั้งนี้ ในคำสั่งค้นหาและแสดงผลเริ่มต้น (`GetSuggestions` และ `GetTopWords`) จะใช้การเรียงลำดับพิเศษ (SQL Custom Ordering) เพื่อรับประกันว่า `ล้างเครื่อง`, `กระดาษติด`, `สีไม่ครบ` จะปรากฏเป็นปุ่มแนะนำ 3 คำแรกเสมอ แม้ว่าจะมีการเรียนรู้คำศัพท์ใหม่เพิ่มเติมเข้ามาในฐานข้อมูลก็ตาม

## 4. ข้อกำหนดหน้าจอและการทำงาน (UI & Functional Specification)

### 4.1 การตั้งค่าฟอนต์ขนาดใหญ่และการแสดงผลภาษาไทย (Minimum 16pt Font Size)
- **เกณฑ์ขนาดฟอนต์ขั้นต่ำ 16pt ทั่วทั้งโปรแกรม:** ทุกคอนโทรลบนหน้าจอ (`Form1` และ `SettingsForm`) ต้องใช้ฟอนต์ขนาด **ไม่ต่ำกว่า 16pt** เพื่อความชัดเจน อ่านง่าย เหมาะสำหรับหน้าจอร้านค้าและการสัมผัส
  - **ฟอนต์มาตรฐานของฟอร์ม:** **`Segoe UI, 16pt`** หรือ **`Tahoma, 16pt`**
  - **ช่องกรอกข้อมูลและป้ายข้อความ (TextBox, Label, DateTimePicker):** ขนาด `16pt`
  - **ตารางรายการ (DataGridView Header & Cell Content):** ขนาด `16pt`
  - **ปุ่มคำสั่งหลัก:** ขนาด `16pt` (Bold)
  - **ปุ่มคำแนะนำอาการเสีย (Pill Suggestion Buttons):** ขนาด `13.5pt` (ลดขนาดลงเล็กน้อยจาก 16pt เพื่อให้วางเรียงได้กะทัดรัด สบายตา ไม่กินพื้นที่)
  - **หัวข้อหลัก/ชื่อโปรแกรม (Header Title):** ขนาด `20pt - 22pt (Bold)`
- **การปรับระยะความสูงของ Control เพื่อรองรับฟอนต์และการแสดงผล:**
  - ความสูงของช่องกรอกข้อความ (`TextBox` ความสูงอย่างน้อย 40-44px) ป้องกันปัญหาสระและวรรณยุกต์ไทย (สระบน/ล่าง, ไม้เอก, ไม้โท) ตกขอบหรือถูกตัดขาด
  - กำหนดความสูงของแถวใน DataGridView: `RowTemplate.Height = 44px` และ `ColumnHeadersHeightSizeMode.EnableResizing` หรือ `ColumnHeadersHeight = 44px`
  - ปรับขนาดแถบคำแนะนำอาการเสีย `pnlWordSuggestions` เป็น **2 บรรทัด** (ความสูง 88px, `WrapContents = true`) รองรับการแสดงผลปุ่มคำแนะนำ 8 คำพร้อมกันอย่างเป็นระเบียบ โดยมี 3 คำสำคัญ ("ล้างเครื่อง", "กระดาษติด", "สีไม่ครบ") ปรากฏอยู่ลำดับหน้าสุดเสมอ
- เปิดใช้งานระบบ High DPI ผ่าน `ApplicationConfiguration.Initialize()` ใน `Program.cs`

### 4.2 โครงสร้างหน้าจอหลัก (`Form1`)
หน้าจอหลักแบ่งออกเป็น 4 ส่วนการทำงานที่ชัดเจน:

#### ส่วนที่ 1: แถบหัวเรื่องและการตั้งค่าร้าน (Top Header & Settings Panel)
- แสดงชื่อโปรแกรมและสถานะร้านค้าปัจจุบัน
- ปุ่ม **"⚙️ ตั้งค่าข้อมูลร้าน" (`btnShopSettings`)**: เมื่อคลิก จะเปิดหน้าต่างป็อปอัป (`SettingsForm.ShowDialog(this)`) เพื่อให้ผู้ใช้แก้ไขชื่อร้านและที่อยู่/เบอร์โทรได้ทันที เมื่อบันทึกแล้ว หน้าจอหลักและระบบพิมพ์จะอัปเดตข้อมูลตามค่าใหม่ทันทีโดยไม่ต้องรีสตาร์ต

#### ส่วนที่ 2: ฟอร์มออกใบงานใหม่ / แก้ไขข้อมูล (Ticket Entry/Edit Form)
- **เลขที่ใบงาน (`txtJobNo`)**: แสดงเลขที่ใบงาน (สร้างอัตโนมัติในโหมดงานใหม่ หรือแสดงเลขที่เดิมในโหมดแก้ไข) แบบ Read-only หรือแก้ไขได้
- **วันที่รับซ่อม (`dtpJobDate` หรือ `txtJobDate`)**: บันทึกวันและเวลาที่รับเครื่องซ่อม
- **ชื่อลูกค้า (`txtCustomerName`)**: ช่องกรอกชื่อลูกค้า (`TextBox`) บังคับกรอก
- **อุปกรณ์และอาการเสีย (`txtDeviceSymptom`)**: ช่องกรอกรายละเอียดอุปกรณ์และอาการเสีย (`TextBox` แบบ `Multiline = true`, `ScrollBars = Vertical`, `WordWrap = true`)
- **แถบแนะนำคำศัพท์สไตล์ Gboard (`pnlWordSuggestions`)**: แถบแนวนอน `FlowLayoutPanel` วางอยู่ใต้ช่องกรอกอาการเสียโดยตรง แสดงปุ่มคำแนะนำแบบไดนามิก 3-5 ปุ่ม (ฟอนต์ 16pt)
- **ตัวเลือกระบบพิมพ์ (`cboPrintFormat`)**: เมนู Dropdown (ComboBox ฟอนต์ 16pt) ให้ผู้ใช้เลือกขนาดกระดาษและเครื่องพิมพ์:
  - `📄 กระดาษ A4 (แบ่ง 2 ส่วน: ร้านค้า / ลูกค้า)`
  - `🧾 สลิป POS 58mm (พิมพ์แบบ Bitmap ภาษาไทยคมชัด)`
- **ตัวเลือกเครื่องพิมพ์ปลายทาง (`cboTargetPrinter`)**: เมนู Dropdown (ComboBox ฟอนต์ 16pt) ดึงรายชื่อเครื่องพิมพ์ทั้งหมดที่ติดตั้งใน Windows (`PrinterSettings.InstalledPrinters`) เพื่อให้ผู้ใช้สามารถเลือกเจาะจงเครื่องพิมพ์ปลายทางได้ทันที (รองรับทั้งเครื่องพิมพ์เริ่มต้น, เครื่องพิมพ์ A4, และเครื่องพิมพ์สลิปความร้อน POS 58mm) พร้อมระบบช่วยสลับเครื่องพิมพ์อัตโนมัติเมื่อเลือกขนาดกระดาษ 58mm
- **ปุ่ม "🔄 เคลียร์หน้าจอ (งานใหม่)" (`btnClear`)**: รีเซ็ตช่องกรอกทั้งหมดเพื่อเตรียมรับงานซ่อมใหม่ และสร้างเลขที่ใบงานถัดไปอัตโนมัติ
- **ปุ่ม "💾 บันทึกและพิมพ์" (`btnSaveAndPrint`)**: 
  - ตรวจสอบความถูกต้องของข้อมูล (Validation) หากไม่กรอกชื่อลูกค้าหรืออาการเสีย จะแสดงข้อความแจ้งเตือน
  - บันทึกลงตาราง `RepairJobs` (หากเป็นงานใหม่จะ `INSERT`, หากเลือกจากตารางจะ `UPDATE`)
  - **ตัดคำศัพท์และบันทึกลง `WordDictionary` อัตโนมัติ** เพื่อให้ระบบเรียนรู้คำศัพท์ใหม่ของร้านค้าอย่างต่อเนื่อง
  - สั่งเปิดหน้าต่างตัวอย่างการพิมพ์ (Print Preview) ทันทีตามรูปแบบกระดาษที่เลือก (A4 หรือ สลิป 58mm)
  - อัปเดตรายการใน DataGridView ให้เห็นงานล่าสุดทันที

#### ส่วนที่ 3: แผงค้นหาใบงานเก่า (Search Panel)
- **ช่องค้นหา (`txtSearch`)**: ช่องกรอกคำค้นหา รองรับทั้ง "เลขที่ใบงาน" หรือ "ชื่อลูกค้า"
- รองรับการค้นหาแบบพิมพ์แล้วกรองทันที (`TextChanged` event) หรือกดปุ่มค้นหา
- แสดงผลลัพธ์ในตาราง `DataGridView` โดยเรียงจากงานล่าสุดไปหางานเก่าสุดเสมอ (`ORDER BY Id DESC`)

#### ส่วนที่ 4: ตารางแสดงรายการและการโต้ตอบ (DataGridView & Re-print)
- **ตารางแสดงผล (`dgvRepairJobs`)**:
  - แสดงคอลัมน์: เลขที่ใบงาน (`JobNo`), วันที่ (`JobDate`), ชื่อลูกค้า (`CustomerName`), อุปกรณ์และอาการเสีย (`DeviceSymptom`)
  - รูปแบบการเลือก: `SelectionMode = FullRowSelect`, `MultiSelect = false`, `ReadOnly = true`
- **การดับเบิลคลิกแถว (`CellDoubleClick`) หรือเลือกแถว**:
  - ดึงข้อมูลของใบงานที่เลือกขึ้นมาแสดงบนช่องกรอกข้อมูลในส่วนที่ 2 ทันที
  - เปลี่ยนสถานะของฟอร์มเป็น "โหมดแก้ไขใบงาน"
- **ปุ่ม "🖨️ พิมพ์ใบงานซ้ำ" (`btnPrintAgain`)**:

### 4.3 ข้อกำหนดระบบแนะนำคำศัพท์อัตโนมัติสไตล์ Gboard (Word Suggestion Bar Specification)

ระบบแนะนำคำศัพท์ทำงานเสมือนคีย์บอร์ดอัจฉริยะ (เช่น Gboard หรือ iOS QuickType) เพื่อช่วยให้ช่างซ่อมบันทึกอาการเสียได้อย่างรวดเร็วโดยไม่ต้องพิมพ์ข้อความซ้ำๆ:

```
┌────────────────────────────────────────────────────────┐
│ อุปกรณ์และอาการเสีย:                                   │
│ โน้ตบุ๊ก Asus เปิดไม่                                   │
└────────────────────────────────────────────────────────┘
┌────────────────────────────────────────────────────────┐
│ [💡 เปิดไม่ติด ] [💡 เปิดไม่ขึ้นภาพ ] [💡 เปิดเครื่องไม่ติด ]│  <-- FlowLayoutPanel
└────────────────────────────────────────────────────────┘
```

#### 1) คุณลักษณะของแถบคำแนะนำ (`FlowLayoutPanel`):
- วางตำแหน่งอยู่ใต้ `txtDeviceSymptom` โดยตรง
- กำหนดความสูง 54-58px, `WrapContents = false`, `AutoScroll = true` (แนวนอน) เพื่อรองรับปุ่มคำแนะนำขนาดฟอนต์ 16pt
- กำหนดสีพื้นหลังโทนอ่อนสบายตา (`BackColor = Color.FromArgb(245, 247, 250)`) และระยะ Padding ที่เหมาะสม

#### 2) ตรรกะการดึงคำศัพท์แบบเรียลไทม์ (Real-Time Token Extraction & Lookup):
- ดักจับเหตุการณ์ `TextChanged` และ `KeyUp` ของ `txtDeviceSymptom`:
  - ดึงตำแหน่งเคอร์เซอร์ (`SelectionStart`) ปัจจุบัน
  - ค้นหาคำสุดท้ายที่กำลังพิมพ์ (Current Token) โดยตัดจากสัญลักษณ์เว้นวรรค (`' '`), เครื่องหมายจุลภาค (`','`), หรือการขึ้นบรรทัดใหม่ (`'\n'`)
  - หาก Current Token ไม่ว่างเปล่า: ส่งคำค้นหาไปยังฐานข้อมูลด้วยคำสั่ง:
    ```sql
    SELECT WordText FROM WordDictionary 
    WHERE WordText LIKE '%' || $token || '%' 
    ORDER BY UsageCount DESC, length(WordText) ASC 
    LIMIT 5;
    ```
  - หากช่องกรอกว่างเปล่า หรือเพิ่งเว้นวรรค (เริ่มต้นคำใหม่): แสดงคำศัพท์ยอดนิยม 5 อันดับแรก (`ORDER BY UsageCount DESC LIMIT 5`) เป็นคำแนะนำเริ่มต้นทันที

#### 3) รูปลักษณ์และการโต้ตอบของปุ่มคำแนะนำ (Pill Buttons Interaction):
- นำผลลัพธ์คำศัพท์ 3-5 คำมาสร้างเป็นปุ่มกดขนาดกะทัดรัด (Pill Button):
  - สไตล์ปุ่ม: `FlatStyle = Flat`, `Cursor = Cursors.Hand`, สีตัวอักษรคมชัด
  - ขนาดฟอนต์: **`Segoe UI, 16pt`** หรือ **`Tahoma, 16pt`** ตามเกณฑ์ขั้นต่ำ 16pt ทั่วทั้งหน้าจอ
- **เมื่อคลิกปุ่มคำแนะนำ:**
  1. ลบคำสุดท้ายที่ผู้ใช้กำลังพิมพ์อยู่ (Current Token) ออก
  2. แทรกคำศัพท์จากปุ่มที่คลิกเข้าไปแทนที่
  3. **เติมช่องว่าง (Space `" "`) ต่อท้ายคำอัตโนมัติ** เพื่อให้ผู้ใช้สามารถคลิกคำถัดไปหรือพิมพ์คำใหม่ต่อได้ทันทีโดยไม่ต้องกด Spacebar
  4. เลื่อนเคอร์เซอร์ไปที่ตำแหน่งท้ายสุดของข้อความ (`txtDeviceSymptom.SelectionStart = txtDeviceSymptom.Text.Length`)
  5. คืนโฟกัสกลับไปยังช่องกรอก (`txtDeviceSymptom.Focus()`) เพื่อให้พิมพ์ต่อเนื่องได้อย่างลื่นไหล
- ผู้ใช้ยังคงพิมพ์คำศัพท์ใหม่ได้อย่างอิสระ 100% ไม่ถูกจำกัดเฉพาะคำในระบบ

#### 4) ระบบการเรียนรู้คำศัพท์ใหม่อัตโนมัติ (Self-Learning Vocabulary on Save):
- ในขั้นตอนที่ผู้ใช้กดปุ่ม **"💾 บันทึกและพิมพ์" (`btnSaveAndPrint`)**:
  - ระบบจะนำข้อความในช่องอาการเสียมาทำการตัดคำ (Tokenize) โดยแยกตามเครื่องหมายวรรคตอนและการเว้นวรรค
  - กรองเฉพาะคำที่มีความยาวตั้งแต่ 2 ตัวอักษรขึ้นไป และไม่ใช่ตัวเลขเดี่ยวหรือสัญลักษณ์ล้วน
  - บันทึกลงตาราง `WordDictionary` ด้วยคำสั่ง Upsert (SQLite `ON CONFLICT`):
    ```sql
    INSERT INTO WordDictionary (WordText, UsageCount) 
    VALUES ($word, 1) 
    ON CONFLICT(WordText) 
    DO UPDATE SET UsageCount = UsageCount + 1;
    ```
  - ส่งผลให้คำศัพท์ที่ช่างซ่อมใช้บ่อยจะมีความถี่ (`UsageCount`) สูงขึ้นเรื่อยๆ และคำใหม่ที่ไม่เคยมีในระบบจะถูกเพิ่มเข้าคลังคำศัพท์โดยอัตโนมัติสำหรับการแนะนำในครั้งถัดไป

### 5.1 การตั้งค่าหน้ากระดาษและระยะขอบ
- **ขนาดกระดาษ:** A4 แนวตั้ง (Portrait)
  - พิกัดในระบบ GDI+ (100 หน่วยต่อนิ้ว): กว้าง **827 หน่วย**, สูง **1169 หน่วย**
- **ระยะขอบ (Margins):** อย่างน้อย 50 หน่วย (ซ้าย=50, ขวา=50, บน=50, ล่าง=50)
  - ความกว้างพื้นที่พิมพ์ได้: `827 - 50 - 50 = 727 หน่วย` (พิกัด X จาก 50 ถึง 777)
  - เพื่อรองรับทั้งเครื่องพิมพ์ระบบ Inkjet และ Laser โดยไม่ตกขอบกระดาษ

### 5.2 การแบ่งครึ่งหน้ากระดาษ (Dual Halves Layout)
- **เส้นคั่นกึ่งกลางหน้ากระดาษ:** อยู่ที่ตำแหน่งแนวนอน **`Y = 584`** (กึ่งกลางของความสูง 1169)

- **ส่วนบน (Upper Half):** ครอบคลุมพิกัด Y ตั้งแต่ 50 ถึง 560
  - มุมบนขวาแสดงข้อความกำกับ: **`"(ส่วนของร้านค้า)"`**
- **ส่วนล่าง (Lower Half):** ครอบคลุมพิกัด Y ตั้งแต่ 605 ถึง 1115
  - มุมบนขวาแสดงข้อความกำกับ: **`"(ส่วนของลูกค้า)"`**

### 5.3 องค์ประกอบภายในแต่ละส่วน (Top & Bottom Content - Minimum 16pt Font พร้อมจุดเน้น)
ทั้งสองส่วนจะดึงข้อมูลชุดเดียวกันมาจัดวางอย่างสมมาตร โดยกำหนด **ขนาดฟอนต์ทุกจุดขั้นต่ำ 16pt (Minimum 16pt Font Size)** พร้อมเน้นจุดสำคัญให้อ่านง่าย สบายตา:
1. **หัวกระดาษ (Header):**
   - ชื่อร้านค้า (`ShopName`): ฟอนต์ตัวหนาขนาด **21pt Bold** (`Segoe UI, 21pt`)
   - **เน้นที่อยู่และเบอร์โทรร้าน (`ShopAddress`):** ฟอนต์ตัวหนาขนาด **16pt Bold** ชัดเจน โดดเด่น
   - ป้ายกำกับสำเนาที่มุมขวาบน (`copyTag`): ฟอนต์ตัวหนาขนาด **16pt Bold** (`(ส่วนของร้านค้า)` หรือ `(ส่วนของลูกค้า)`)
2. **หัวเรื่องเอกสาร (Document Title):** ข้อความ `"ใบรับซ่อมสินค้า (Repair Ticket)"` ฟอนต์ตัวหนาขนาด **19pt Bold** กึ่งกลางหน้ากระดาษ
3. **ข้อมูลใบงาน (Metadata ฟอนต์ 16pt พร้อมเน้นจุดสำคัญ):**
   - **เน้นเลขที่ใบงาน (`JobNo`):** ป้ายกำกับ 16pt Bold, **ข้อมูลเลขที่ใบงานเน้นด้วย 17pt Bold สีคมชัด**
   - วันที่รับซ่อม (`JobDate`): ป้ายกำกับ 16pt Bold, ข้อมูล 16pt Regular
   - ชื่อลูกค้า (`CustomerName`): ป้ายกำกับ 16pt Bold, ข้อมูล 16pt Regular
   - **เน้นเบอร์โทรลูกค้า (`CustomerPhone`):** ป้ายกำกับ 16pt Bold, **ข้อมูลเบอร์โทรศัพท์เน้นด้วย 17pt Bold** เพื่อให้มองเห็นและติดต่อได้ทันที
4. **กรอบแสดงรายละเอียดอุปกรณ์และอาการเสีย (Device & Symptom Box ฟอนต์ 16pt):**
   - หัวข้อ "อุปกรณ์และอาการเสีย:": ฟอนต์ **16pt Bold**
   - ตีกรอบสี่เหลี่ยมชัดเจน (`DrawRectangle`)
   - ข้อความอาการเสียภายในกรอบแสดงด้วยฟอนต์ **16pt Regular** พร้อมตัดขึ้นบรรทัดใหม่อัตโนมัติ (`WordWrap`) ด้วย `StringFormat` มีพื้นที่กว้างขวางบรรจุข้อความยาวได้ดีขึ้น
5. **ช่องลงนาม (Signature Area ฟอนต์ 16pt):**
   - ด้านซ้าย: ข้อความ `"ลงชื่อ ................................ (ผู้รับ)"` ฟอนต์ **16pt Regular**
   - ด้านขวา: ข้อความ `"ลงชื่อ ................................ (ลูกค้า)"` ฟอนต์ **16pt Regular**

### 5.4 ระบบพิมพ์สลิปความร้อน POS ขนาด 58mm ด้วยระบบ Bitmap (58mm Thermal Slip via Bitmap Engine)

เพื่อรองรับเครื่องพิมพ์ใบเสร็จความร้อนขนาดเล็กหน้าร้าน (เช่น Xprinter, Gprinter, POS-58 USB/Bluetooth) และ **แก้ปัญหาภาษาไทย 100%**:

```
┌──────────────────────────────────────┐ (ความกว้าง 58mm / 384px)
│       ร้านซ่อมอุปกรณ์ด่วน (Smart)       │ [ฟอนต์ตัวหนา จัดกึ่งกลาง]
│  123/45 ถ.สุขุมวิท ... โทร. 081-234-5678 │
│ ------------------------------------ │
│           [ ส่วนของร้านค้า ]         │
│ ใบรับซ่อม: 261119-100524              │
│ วันที่: 19/11/2026 14:30              │
│ ลูกค้า: คุณสมชาย ใจดี                 │
│ ------------------------------------ │
│ อุปกรณ์/อาการเสีย:                    │
│ โน้ตบุ๊ก Asus เปิดไม่ติด เสียบชาร์จ     │
│ ไฟไม่เข้า (จอแตกมุมขวา)              │
│ ------------------------------------ │
│ ลงชื่อ .................... (ผู้รับ)   │
│ ลงชื่อ .................... (ลูกค้า)  │
│ - - - - - [ ฉีกตามรอยปรุ ] - - - - - │
│           [ ส่วนของลูกค้า ]         │
│         (พิมพ์เนื้อหาคู่ฉบับต่อเนื่อง)   │
└──────────────────────────────────────┘
```

#### 1) ปัญหาทางเทคนิคของเครื่องพิมพ์ POS 58mm ทั่วไป:
- เครื่องพิมพ์ 58mm ราคาประหยัดในท้องตลาดมักใช้คำสั่งแบบ ESC/POS Direct Text ซึ่งต้องพึ่งพาตารางรหัสภาษาไทยของเครื่อง (Code Page 874 / TIS-620)
- **ปัญหาที่พบเป็นประจำ:** เฟิร์มแวร์ของเครื่องพิมพ์ไม่มีรหัสภาษาไทย ทำให้พิมพ์ออกมาเป็น `????` หรือตัวอักษรจีนขยะ หรือหากมีรหัสไทย วรรณยุกต์และสระ (สระบน/ล่าง ไม้เอก ไม้โท) มักจะซ้อนทับกัน ตัวหนังสือลอย หรือตกขอบ ไม่สามารถอ่านข้อความได้

#### 2) สถาปัตยกรรมการพิมพ์ด้วย GDI+ Bitmap (Bitmap Graphic Printing Architecture):
ระบบแก้ไขปัญหานี้อย่างเด็ดขาดด้วยการ **วาดสลิปทั้งใบลงบนหน่วยความจำภาพ (In-Memory Bitmap) ก่อนสั่งพิมพ์**:
1. **การคำนวณขนาดภาพ (Canvas Sizing):**
   - ความกว้างกระดาษ 58mm: กำหนดพื้นที่พิมพ์มาตรฐานที่ **384 พิกเซล** (ประมาณ 48mm ที่ความละเอียด 203 DPI มาตรฐานเครื่อง POS ทั่วไป)
   - ความสูงของภาพ (Height): คำนวณแบบไดนามิกตามความยาวของข้อความอาการเสียจริง (Auto-Sized Canvas) โดยวัดขนาดผ่าน `Graphics.MeasureString`
2. **การเรนเดอร์ข้อความภาษาไทยด้วย GDI+:**
   - สร้างวัตถุ `Bitmap slipBmp = new Bitmap(384, totalHeight);`
   - ใช้ `Graphics g = Graphics.FromImage(slipBmp);`
   - กำหนด `g.TextRenderingHint = TextRenderingHint.SingleBitPerPixelGridFit;` (หรือ `AntiAliasGridFit`) และ `g.Clear(Color.White);`
   - วาดข้อความภาษาไทยทั้งหมดด้วยฟอนต์ของ Windows เช่น `Tahoma` หรือ `Segoe UI` ซึ่งระบบปฏิบัติการ Windows จะจัดการผสานสระ วรรณยุกต์ไทย 3 ระดับ และการตัดคำภาษาไทยให้อย่างสมบูรณ์แบบ 100% ไม่มีปัญหาตัวอักษรเพี้ยนหรือสระลอยเด็ดขาด
3. **การส่งพิมพ์เข้าเครื่องพิมพ์ผ่าน `PrintDocument`:**
   - ในอีเวนต์ `OnPrintPage(PrintPageEventArgs e)`:
     ```csharp
     // วาดภาพ Bitmap สลิปลงบนหน้ากระดาษของเครื่องพิมพ์ POS
     e.Graphics.DrawImage(slipBmp, 0, 0);
     ```
   - เครื่องพิมพ์จะรับข้อมูลเป็นภาพลายจุด (Raster Graphic) ส่งผลให้พิมพ์ภาษาไทยได้คมชัด ชัดเจน ไม่ขึ้นอยู่กับชิปฟอนต์หรือเฟิร์มแวร์ของเครื่องพิมพ์อีกต่อไป

#### 3) การพิมพ์ 2 สำเนาต่อเนื่องบนม้วนสลิปเดียว (Dual Copies on Continuous Roll):
- เครื่องพิมพ์ 58mm จะพิมพ์ 2 สำเนาต่อเนื่องในคำสั่งเดียว:
  1. **สลิปท่อนแรก:** กำกับหัวข้อ `[ ส่วนของร้านค้า ]` สำหรับให้ร้านเก็บไว้เป็นหลักฐานแนบตัวเครื่อง
  2. **เส้นแบ่งรอยฉีก:** วาดเส้นประ `- - - ฉีกตามรอยปรุ - - -` เพื่อให้ช่างฉีกแบ่งได้อย่างชัดเจน
  3. **สลิปท่อนที่สอง:** กำกับหัวข้อ `[ ส่วนของลูกค้า ]` สำหรับมอบให้ลูกค้านำมายื่นรับเครื่องคืน
- มีการเว้นระยะท้ายกระดาษ (Feed Margin) เล็กน้อยเพื่อให้ใบเสร็จเลื่อนพ้นใบมีดฉีกกระดาษของเครื่องพิมพ์พอดี

## 6. ข้อกำหนดความปลอดภัยและการจัดการข้อผิดพลาด (Security & Error Handling)

1. **ป้องกัน SQL Injection 100%:** ทุกคำสั่ง SQL ต้องใช้พารามิเตอร์ของ `SqliteParameter` เท่านั้น ห้ามนำสตริงของผู้ใช้มาต่อคำสั่ง SQL โดยตรง
2. **การคืนหน่วยความจำ (Resource Cleanup):** วัตถุที่สืบทอด `IDisposable` (เช่น `SqliteConnection`, `SqliteCommand`, `Font`, `Pen`, `Brush`) ต้องถูกห่อหุ้มด้วยบล็อก `using` เสมอ เพื่อป้องกัน memory leak และปัญหาไฟล์ฐานข้อมูลถูกล็อก
3. **การตรวจสอบค่าว่าง (Input Validation):** ก่อนบันทึกใบงาน ต้องตรวจสอบว่าชื่อลูกค้าและอาการเสียไม่เป็นค่าว่าง
4. **การจัดการข้อผิดพลาด (Try-Catch Envelopes):** การเชื่อมต่อฐานข้อมูลและการสั่งพิมพ์ต้องมีบล็อก `try-catch` พร้อมแสดงกล่องข้อความภาษาไทย (`MessageBox.Show`) ที่เข้าใจง่าย ไม่เกิดการแครชของโปรแกรม
